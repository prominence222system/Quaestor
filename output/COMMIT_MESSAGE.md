feat: 감시 루프에 감독용 HTTP 계약면을 붙인다

Foreman 이 대상별 특수 코드 없이 이 감시자를 읽어가도록 하는
`_guides/SUPERVISED_TOOL_CONTRACT.md` 의 대상 쪽 절반을 구현했다.
127.0.0.1:3210 에서만 듣는 `GET /api/health`(HTTP 생존)·`GET /api/status`
(003 의 `deriveState()` 를 재판정 없이 그대로 투영, 측정 건강)를 열었고,
두 값을 의도적으로 분리했다 — 합치면 "프로세스는 살아있고 측정은
3주째 죽어 있다"를 다시 초록불로 표시하는 실패가 새 층에서 반복된다.

컨트롤 서버는 감시 루프의 부가 기능이지 본체가 아니다. 기동이
포트 점유 등으로 실패해도 예외가 새지 않고 `started:false` 로만
보고되며, `watch-loop.js` 의 폴링 루프는 그와 무관하게 계속 돈다
(never-brick). `getSnapshot()` 은 기동 시점 값을 캡처하지 않는
라이브 클로저로 만들어 `/api/status` 가 항상 최신 관측을 반영하게
했고, 새로운 파일 I/O 를 추가하지 않도록 `pollOnce()` 가 이미 읽는
값만 재사용했다.

인증은 `Authorization: Bearer` + `crypto.timingSafeEqual` 기반 상수시간
비교로 얹었고, 토큰이 설정되지 않은 현재 실측 상태에서는 인증 없이
허용하되 방어선을 `127.0.0.1` 바인딩 하나로 유지한다 — 잠그는 쪽으로
기본값을 바꾸면 Foreman 클라이언트가 붙는 순간 전부 401 만 보게 된다.
`POST /api/stop` 은 계약상 선택 조항이지만, 이 제품의 정지가 안전장치
자체를 끄는 동작이라 확인 없는 호출을 허용할 수 없어 의도적으로
미구현(501)으로 남겼다 — 근거는 코드 주석과 `PROJECT_INTENT.md` 에 있다.

이어지는 검증 라운드에서는 그동안 임의 포트(`port: 0`)로만 검증되던
통합 테스트를 계약이 못 박은 기본 주소(3210)에 `readConfig()` 조립
경로 그대로 실바인딩해 검증했고, 계약 체크리스트 전 항목의 충족/의도적
미구현/대상 밖 판정과 구현이 계약 예시와 갈라지는 두 지점(`id`,
`tokenFrom`)을 `CONTINUATION.md` 에 인수인계 기록으로 남겨 Foreman 쪽
절반이 잘못된 키로 조용히 붙는 것을 막았다. 마지막으로, 그동안 fetch 가
보내는 선량한 요청만으로 검증되던 계약면을 후행 슬래시·미지 메서드·
비정상 인증 헤더 같은 역경로와, 소켓 강제종료·비HTTP 바이트·동시 요청
같은 실제 장애 시나리오 앞에서도 검증해 "계기판이 차단기를 죽이지
않는다"는 조항을 코드가 아니라 관측으로 확정했다.

`deriveDesired()` 의 임계·히스테리시스, STOP.json 의 위치·이름·스키마,
수동 STOP 우선 규칙은 전 라운드에 걸쳐 한 줄도 건드리지 않았다.
